# Discovery notes

Before trusting the model, talk to someone who handles communications requests (a university news office,
a student organization's social media lead, a newsletter editor). Aim for two or three 20 minute conversations.
Put short quotes and what you changed because of them in the README.

## Questions

1. Where do requests reach you today? (Slack, email, forms, hallway, DMs.) Roughly how many a week?
2. Walk me through the last request you got. What did you have to figure out before you could start?
3. Which requests get sent to the wrong person most often? What happens when they do?
4. What information is usually missing from a request? (Deadline, audience, assets, approvals.)
5. How do you decide what is urgent?
6. How often do you search for something you did before ("didn't we announce this last year?")? Where do you look?
7. What would you never want an automated tool to do on its own?
8. If a tool sorted requests for you, how sure would it need to be before you let it skip a person?
9. How would you know the tool was actually saving you time?

## Measuring time saved

Before: time a person spends reading, routing and replying to a request by hand (ask them to estimate, or
time five real ones). After: time to check the bot's routing and edit its draft. Report the difference per
request and per week, with the number of requests it is based on.
